# (Sparse) Mixture of Experts (MoE)
For dense model, every parameter is activated for every token. This imposes challenge when scaling up LLM. MoE breaks this rule: You can increase model capacity (more parameters) without increasing compute cost per token as much. 

Instead of a single dense feed-forward block (MLP), (sparse) MoE has many experts (say 64–256). Each token is routed to only TopK experts (often K=2). MoE becomes standard for frontier models.

# Token Routing
* B: token batch
* D: d_model dim
* E: number of experts
* K: number of experts to route for each token
* F: hidden dim in FFW

Suppose the input $x$ has shape [B, D]. We first compute the which experts each token should be routed to by einsum [B, D], [D, E] => [B, E]. Then we select TopK experts [B, E] => [B, K].

Now we route the tokens to each expert. Each expert will recieve all the tokens it needs to process as $x_{i}$ of shape [B', D].

Suppose we use FFN in MLP (GLU is more common). Then $y=f(xW_{1})W_{2}$ where $W_{1}\in\R^{D\times F}$, $W_{1}\in\R^{F\times D}$ and $f$ is an element-wise acitvation function.
## Reparameterization
For each token, we need to sample TopK experts. The problem here is that once we sample the experts, we lose the gradient. 

How to interpret this? Let's say we have a binary distribution where $\mathbb{P}_{\theta}(X=0)=\theta$ and $\mathbb{P}_{\theta}(X=1)=1-\theta$ where $\theta \in [0, 1]$ is our parameter. We can sample from this distribution. Let's say we have samples [0, 1, 1, 0, 0, 0, 1, 1]. Those samples do not have $\theta$ associated anymore. Thus, we cannot do backprop. This is the reason why we cannot directly sample experts using softmax.

A typical solution here is to do reparametrization. Instead of sampling from $\mathbb{P}_{\theta}$, we sample from a standalone distribution, e.g. Gaussian $\epsilon \sim N(0, 1)$ and transform the sample by $g_{\theta}(\epsilon)$ to get our desired samples. 

## Gumbel Max
Gumbel Max is used for the reparameterization trick when sampling experts. Suppose we have a discrete distribution $p_{i}$ where $i=1, \dots, k$. To sample, we can do following

$\argmax_{i}\left(\log p_{i}-\log(-\log \epsilon_{i})\right)_{i=1}^{k}, \epsilon_{i}\sim U[0, 1]$.

Note $\epsilon_{i}$ is sampled from a uniform distribution independent of $\theta$.

However, $\argmax$ is still not differentiable. The smooth approximation of $\argmax$ is

$softmax\left(\left(\log p_{i}-\log(-\log \epsilon_{i})\right)/\tau\right)_{i=1}^{k}, \epsilon_{i}\sim U[0, 1]$

where $\tau$ is temperature. As $\tau \rightarrow 0$, we get $\argmax$.

Still, we need to select K experts. This process is again non-differentialbe. Straight-Through trick is applied in practice where in the forward pass, we do hard TopK expert selection, e.g. we select K experts and route the token to these k experts. 

In backward pass, we assume we did softmax in the forward pass and distribute gradient to all experts based on softmax. 
# Implementation

## Token Routing
Here comes the confusing part. In many opensource implementation, Gumbel-Softmax is not used. Instead, people usually do softmax and then topk in the forward pass. For example, here is the [implementation](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_moe/modeling_qwen3_moe.py#L197) of MoE from Qwen3

```python
batch_size, sequence_length, hidden_dim = hidden_states.shape
hidden_states = hidden_states.view(-1, hidden_dim)
# router_logits: (N, E)
router_logits = self.gate(hidden_states)
routing_weights = F.softmax(router_logits, dim=1, dtype=torch.float)
routing_weights, selected_experts = torch.topk(routing_weights, self.top_k, dim=-1)
```
Note `torch.topk` is deterministic. It simply returns the largest k values without sampling. 

Also note `torch.topk` returns both weights and indices. The indices are non-differentiable but the weights are still differentiable. So, the gradient could still backprop via the weights.

The downside of this is that the gradient only backprops through the TopK experts. All other experts will not get any gradient update. Together with the fact that TopK here is deterministic, it can create issues, like experts imbalancing in training. The more an expert gets updated, the more likely the token is routed to it. For less updated experts, they will be undertrained.

Gumbel-Softmax can handle this issue better as it introduces stochasticity when sampling.

## Sparse MoE Computation
The following code also comes from Qwen3 sparse MoE. What it does is
1. After TopK, it converts the expert choice to mask using onehot encoding
2. Loop over experts with token assignment and do FFW
3. No expert capacity and no token drop.

```python
# One hot encode the selected experts to create an expert mask
# this will be used to easily index which expert is going to be sollicitated
expert_mask = torch.nn.functional.one_hot(selected_experts, num_classes=self.num_experts).permute(2, 1, 0)  # shape [E, K, B] 

# Loop over all available experts in the model and perform the computation on each expert
expert_hit = torch.greater(expert_mask.sum(dim=(-1, -2)), 0).nonzero()
for expert_idx in expert_hit:
    expert_layer = self.experts[expert_idx]
    # expert_mask[expert_idx].squeeze(0): [K, B]
    # idx: indices along first dim (K dim) where expert_mask is True, shape [N]
    # top_x: indices along second dim (B dim) where expert_mask is True, shape [N]
    idx, top_x = torch.where(expert_mask[expert_idx].squeeze(0))

    # Index the correct hidden states and compute the expert hidden state for
    # the current expert. We need to make sure to multiply the output hidden
    # states by `routing_weights` on the corresponding tokens (top-1 and top-2)
    # hidden_states: [B, D] -> [1, B, D] -> [1, N, D] -> [N, D]: N num of tokens assigned to the expert
    current_state = hidden_states[None, top_x].reshape(-1, hidden_dim)
    # routing_weights: [B, K]
    current_hidden_states = expert_layer(current_state) * routing_weights[top_x, idx, None]

    # However `index_add_` only support torch tensors for indexing so we'll use
    # the `top_x` tensor here.
    final_hidden_states.index_add_(0, top_x, current_hidden_states.to(hidden_states.dtype))
final_hidden_states = final_hidden_states.reshape(batch_size, sequence_length, hidden_dim)
return final_hidden_states, router_logits
```

## Gumbel-Softmax Implementation
I haven't found any opensource implementation. So, I asked ChatGPT to generate it for me. The code looks decent.

```python
def gumbel_softmax_topk(logits, k=1, tau=1.0, hard=True, renorm=False, eps=1e-10):
    """
    Gumbel-Softmax Top-k sampling for Mixture-of-Experts routing.

    Args:
        logits : [N, E] float
            Input logits for E experts.
        k : int
            Number of experts to select.
        tau : float
            Temperature for Gumbel-Softmax.
        hard : bool
            If True, apply straight-through hard top-k masking.
        renorm : bool
            If True, renormalize top-k weights to sum to 1 per row.
        eps : float
            Small constant for numerical stability.

    Returns:
        topk_idx : [N, k] long
            Indices of selected experts.
        topk_w : [N, k] float
            Weights for selected experts (renormalized if renorm=True).
        y : [N, E] float
            Full probability distribution (soft if hard=False, hard+soft-gradient if hard=True).
    """
    N, E = logits.shape

    # Sample Gumbel noise
    gumbel = -torch.log(-torch.log(torch.rand_like(logits) + eps) + eps)

    # Gumbel-Softmax probabilities
    y_soft = F.softmax((logits + gumbel) / tau, dim=-1)  # [N, E]

    # Select top-k experts
    topk_w, topk_idx = torch.topk(y_soft, k, dim=-1)  # [N, K]

    if renorm:
        topk_w = topk_w / (topk_w.sum(dim=-1, keepdim=True) + eps)

    if hard:
        # Build hard distribution with straight-through trick
        y_hard = torch.zeros_like(y_soft)
        # No gradient through y_hard as we detach topk_w and no gradient flow through topk_idx
        y_hard.scatter_(1, topk_idx, topk_w.detach())
        # In forward pass, this is essentially y_hard. In backward pass. we get gradient from y_soft. No gradient for y_hard.
        y = y_hard + (y_soft - y_soft.detach())  # soft grad, hard forward
    else:
        y = y_soft

    return topk_idx, topk_w, y
```

## Load Balance
As mentioned before, we want to train all experts equally. Thus in each batch, we hope each token gets roughtly the same number of tokens.

### Load Balance Loss (LBL)
To enforce this, we can add auxiliary loss called Load Balance Loss (LBL). In [Switch Transformers: Scaling to Trillion Parameter Models
with Simple and Efficient Sparsity](https://arxiv.org/pdf/2101.03961), the loss function is defined as

$L_{aux}=\alpha \cdot E \cdot \sum_{i=1}^{E} f_{i}P_{i}$

where $f_{i}$ is the fraction of tokens dispatched to expert $i$

$f_{i}=\frac{1}{N}\sum_{x \in \mathit{B}}1 \{i \in topk (x)\}$

and $P_{i}$ is the fraction of the router probability allocated for expert $i$

$P_{i}=\frac{1}{N}\sum_{x \in \mathit{B}}p_{i}(x)$

The idea is that by using such auxiliary loss function, we should encourage evenly distribution. This loss is widely used in MoE implementation. However, this loss itself seemingly doesn't encourage evenly distribution, meaning if you want to minimize $L_{aux}$, $f_{i}=P_{i}=
1/E$ is not the optimal solution.

In [GShard: Scaling Giant Models with Conditional
Computation and Automatic Sharding](https://arxiv.org/pdf/2006.16668), it mentioned that the loss is

$\tilde{L}_{aux}=\sum_{i=1}^{E} f_{i}^{2}$

Subject to $\sum_{i=1}^{E}f_{i} = 1$. The optimal solution is $f_{i}=1/E$. The issue here is that we cannot do backprop using $f_{i}$ as it's computed by first sampling then counting. During sampling, we've already lost the gradient. In the paper, it uses a smoother approximation 

$L_{aux}=\sum_{i=1}^{E} f_{i}P_{i}$

because $P_{i}$ contains the gradient.

The question is if $L_{aux}$ is completely wrong, why it's still widely used?  Actually the gradient of this loss function is still valid. The loss itself doesn't make any sense. Let's find out what's the gradient for the loss

$$
\begin{align}
\tilde{L}_{aux}&=\frac{1}{2}\sum_{i=1}^{E} f_{i}^2 \\
&=\frac{1}{2}\sum_{i=1}^{E} \left(P_{i} + SG[f_{i} - P_{i}]\right)^2
\end{align}
$$

where $SG$ is stop gradient. Remeber $P_{i}$ contains the gradient. Let's take the gradient w.r.t. to parameter $\theta$

$$
\begin{align}
\nabla_{\theta}\tilde{L}_{aux}&=\sum_{i=1}^{E} \left(P_{i} + SG[f_{i} - P_{i}]\right)\nabla_{\theta}\left(P_{i} + SG[f_{i} - P_{i}]\right) \\
&=f_{i}\nabla_{\theta}P_{i} \\
&=\nabla_{\theta}L_{aux}
\end{align}
$$
